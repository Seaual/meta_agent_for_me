# Strategic 视角分析 — 题目工厂 Agent Team

## 核心价值主张

将原本需要人类专家 8 小时以上的高难度垂域题目生产工作，转化为 Agent Team 的自动化流水线，核心价值是**质量不降的前提下实现规模化生产**。

具体解决的痛点：
1. **人力瓶颈**：人类完成 50 道题需 8h+，Agent Team 可将边际成本降至接近零
2. **一致性难题**：多专家协作时风格/难度/格式难以统一，Agent 通过标准化模板和验证机制保证一致性
3. **附件管理复杂度**：每题 5-8 个附件、复用限制、格式合规，人工管理容易出错
4. **质量波动**：人类疲劳导致后期题目质量下降，Agent 可持续保持验证标准

---

## 成功指标

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 单题生产时间 | < 2 分钟（含附件匹配） | 从输入题目数量到 CSV 输出的端到端时间 |
| 同质化通过率 | >= 95% | quality-validator 的相似度<=30% 检查 |
| 附件合规率 | 100% | 每题 5-8 个附件、每附件复用<=2 次 |
| 类目覆盖率 | 100%（7 个一级类目） | topic-planner 的覆盖审计 |
| 自动重试成功率 | >= 90% | 验证不通过后自动重试的成功比例 |
| 人类干预频率 | < 5% | 需要人工介入的题目比例 |

## 边界定义

### 在 team 内（核心职责）

1. **主题规划**：从种子池选取/组合主题，确保 7 个类目覆盖
2. **题目生成**：基于模板和主题生成高质量垂域题目（含业务背景、核心任务、关键限制、参考依据）
3. **附件匹配**：从附件清单匹配或调用工具生成，管理复用次数
4. **质量验证**：同质化、时效性、附件合规三重检查
5. **数据协调**：汇总为标准化 CSV，管理自动重试流程
6. **工具脚本调用**：将原有 Python 脚本作为可调用工具使用

### 在 team 外（明确不做）

1. **不替代底层文件操作**：CSV 写入、附件下载等保留为 Python 工具脚本，Agent 只负责决策和调用
2. **不管理种子内容维护**：`seeds/topics.yaml`、`companies.yaml` 的内容更新由外部维护，Agent 只读取使用
3. **不做题目分发/发布**：生成后的 CSV 如何使用（导入题库、上传平台）不在 team 范围内
4. **不做答案/解析生成**：当前需求只聚焦题目本身，不生成参考答案或解析
5. **不做用户权限管理**：不处理多用户协作、审批流、版本控制等
6. **不替代人类终审**：虽然自动重试无需人工审核，但 team 设计应预留人类抽查入口（如输出验证报告供人查看）

## 最小可行架构

基于需求中的 5-agent 设计已是精简版，与原有流水线模块一一对应，无需进一步压缩：

```
用户输入题目数量
    |
    ▼
topic-planner（主题规划）
    |
    ▼
question-generator（题目生成）
    |
    ▼
attachment-matcher（附件匹配）
    |
    ▼
quality-validator（质量验证）← 不通过则返回重写
    |
    ▼
data-coordinator（汇总输出 CSV）
```

**为什么 5 个 agent 是最小可行而非过度设计**：
- 每个 agent 对应原有流水线的一个独立模块，模块间有清晰的数据边界
- 题目生成和附件匹配需要不同的专业知识（业务领域 vs 文件管理）
- 质量验证必须独立于生成者，避免「自我通过」
- data-coordinator 承担重试调度和汇总，是流程的必需闭环

## 扩展路线

### v2 可能加入

1. **答案生成 agent**：为每道题生成参考答案和评分标准
2. **难度分级 agent**：基于专家年限和题目复杂度自动标注难度等级（L1-L5）
3. **批量主题导入**：支持用户上传自定义主题文件，而非仅从种子池选取
4. **多格式输出**：除 CSV 外支持 JSON、XML 等格式，适配不同题库系统
5. **附件自动生成**：当前附件匹配依赖现有清单，v2 可加入根据题目内容自动生成附件的能力（如生成模拟数据表格）

### v3 可能加入

1. **A/B 题目生成**：同一主题生成多个变体，供专家选择最优版本
2. **题库去重引擎**：与现有历史题库比对，避免重复生成相似题目
3. **专家反馈闭环**：收集人类专家对生成题目的评分，反馈优化生成模板
4. **多语言支持**：生成英文版题目，适配国际化场景
5. **实时质量仪表盘**：可视化展示生成进度、质量指标、类目覆盖情况

## 战略风险

- **种子数据质量依赖**：topic-planner 的输出质量完全依赖 `seeds/topics.yaml` 和 `companies.yaml` 的覆盖度和时效性。如果种子数据陈旧或类目不平衡，Agent 无法自行弥补。**缓解**：在 team 的 CLAUDE.md 中明确标注种子数据维护责任方，建议定期审计种子覆盖度。

- **附件复用限制的隐性冲突**：每附件最多复用 2 次，在大量题目生成时可能成为瓶颈（附件库不足导致无法匹配）。**缓解**：attachment-matcher 的提示词中需设计「附件库耗尽」的处理分支（如标记为需人工补充附件，或降级为生成占位符）。

- **自动重试的无限循环风险**：quality-validator 不通过触发重写，如果验证标准过严或生成器有系统性偏差，可能导致无限重试。**缓解**：data-coordinator 必须设置最大重试次数（建议 3 次），超限后标记为「需人工审核」并继续下一题，不阻塞整体流程。

- **垂域知识漂移**：题目涉及 7 个一级类目（金融、房地产、科技研发等），Agent 的通用知识可能不足以生成真正「高难度」的专业题目。**缓解**：在 `prompts/question_template.md` 中注入各领域的关键概念和术语表，或考虑 v2 为每个类目配置专门的「领域知识片段」。

### 独立判断

本次 5-agent 设计（topic-planner / question-generator / attachment-matcher / quality-validator / data-coordinator）是需求驱动的合理设计，理由：
1. 与原有 Python 流水线的 5 个模块一一对应，迁移风险最低
2. 每个 agent 有独立的输入输出边界，数据流清晰
3. 质量验证必须独立于生成，这是不可压缩的底线
4. data-coordinator 的重试调度功能是「无需人工审核」承诺的技术保障，不可省略
